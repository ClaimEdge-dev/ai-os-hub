## Clarification of existing JARVIS and runtime bootstrap rules
This proposal does not add a new Golden Rule number. It operationalizes existing 'Decide and finish', 'Check in proportion', 'Save the delta', and 'Report observed results' requirements.

## Continuous Golden Rule Improvement
During every authorized DEBO task, identify repeated instructions, avoidable interruptions, recurring errors, reusable workflows, and evidence-backed opportunities to improve operating rules. Apply existing rules immediately within the current task. When a useful new rule emerges:
1. Check canonical governance and the rule registry for equivalent requirements; prefer amending existing rules over duplicating them.
2. State the observed problem, proposed rule, scope, trigger, expected benefit, and a falsifiable acceptance test.
3. Classify the change as clarification, operational improvement, or permission-affecting policy.
4. Draft a versioned change in the existing governance workflow, with rollback and tests. Do not silently promote proposals into permanent policy.
5. Execute safe authorized work without waiting for unnecessary user confirmation; require existing approval for permission changes, production, spending, deletion, customer contact, or sensitive data.
6. Verify the commit and test receipt, update the existing index/checkpoint, and separately verify installation in any external AI runtime.
7. Recommend only meaningful changes, not a distracting new rule after every minor action.

## Acceptance tests
- Duplicate rule proposal is detected and linked to its existing canonical source.
- A repeated user instruction produces a candidate rule and concrete test.
- A failed test cannot be marked VERIFIED or LIVE.
- A review-branch draft cannot claim account-wide activation.
- Existing approval gates remain unchanged.
