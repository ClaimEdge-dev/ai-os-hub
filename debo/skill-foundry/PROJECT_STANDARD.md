# DEBO Universal Project Standard v0.1
Applies to every active project and future project. Proposed standard; not proof of deployment.
## Metaphor
Every project is a jobsite. The master dashboard is dispatch, the project folder is the job trailer, branding is the uniform, and evidence is the signed work order.
## Required project profile
project_id, name, owner, description, priority, current_phase, canonical_folder, source_repositories, connected_systems, privacy_class, approvers, next_action, blockers, last_verified_at.
## Project kit
1. BRAND: approved logo variants, palette, fonts, voice, usage rules, asset source, approval record; placeholders until approved.
2. TEMPLATES: letterhead, email signature, proposal, invoice, receipt, estimate, field report, photo report, social post, flyer, business card, presentation, SOP, checklist, meeting notes, intake form.
3. FILES: folder hierarchy, naming convention, index, retention, permissions, revision history, archive.
4. OPERATIONS: client/job registry, work orders, scheduling, evidence, approvals, task register, CRM integrations.
5. MONEY: invoice/revenue register linked to actual work, collections, outstanding balances, refunds, receipts and reconciliation.
6. TECH: source code, schema, connectors, secrets kept outside repository, deployments, test receipts.
7. GOVERNANCE: owner approvals, status evidence, security, rollback and changelog.
## Project lifecycle
INTAKE -> RECOVER -> INVENTORY -> BRAND -> TEMPLATE -> BUILD -> TEST -> REVIEW -> DEPLOY -> OPERATE -> ARCHIVE.
Existing projects should be migrated incrementally, not recreated.
## Status vocabulary
PLANNED / DRAFT / BUILT / TESTED / APPROVED / DEPLOYED / BLOCKED / ARCHIVED. A file or design does not prove deployment.
## Mandatory safeguards
Never publish branding, send communications, change access, move/delete existing files, or issue invoices without appropriate authorization. Private client and business information belongs in approved private storage, not this public repo.
