## Chat/thread lifecycle

Each significant thread is classified:
ACTIVE
REFERENCE
MERGE-INTO-ACTIVE
SUPERSEDED
ARCHIVE-CANDIDATE
KEEP-SEPARATE
NEEDS-REVIEW

Before archive:
1. extract unresolved tasks;
2. preserve durable decisions;
3. file important artifacts;
4. update Project Brain;
5. create Resume Capsule/checkpoint;
6. confirm another thread/project owns active work.

Archive is preferred over deletion.
Deletion requires explicit user approval after inventory.

## ChatGPT mode governance

Invoke chatgpt-surface-router before substantial work.

Do not use:
- Work for a trivial question;
- Deep Research for a single current fact;
- Voice for exact identifiers/legal wording;
- a new chat when the current project thread is healthy;
- a new Project when an existing child Brain owns the domain.

## Cleanup workflow

### Phase 0 — Recovery
Recover canonical Project Registry, Drive roots, Notion controls, GitHub configs, Resume Capsules and project instructions.

### Phase 1 — ChatGPT inventory
Inventory visible Projects, project settings, chats, files/sources, shared projects and obvious duplicates.

### Phase 2 — Classification
For each project/chat:
KEEP
MOVE
MERGE
RENAME
RECOLOR
UPDATE-INSTRUCTIONS
SAVE-AS-SOURCE
ARCHIVE
NEEDS-REVIEW

### Phase 3 — Dry-run
Show exact proposed mutations before destructive/large-scale cleanup.

### Phase 4 — Execute
Use ChatGPT Work / browser where required.
Do reversible moves/renames first.
Archive only after handoff/checkpoint.
Do not delete without explicit approval.

### Phase 5 — Verify
Check project instructions, sources, colors/icons, thread names, canonical links and archive state.

### Phase 6 — Checkpoint
Update DEBO Project Registry + Resume Capsule + change log.

## Context / usage efficiency

- keep 30-50% context headroom on long workflows when practical;
- retrieve targeted sections instead of entire histories;
- summarize/compile current state into Resume Capsules;
- save durable outputs once and reference them;
- use Project context instead of re-pasting;
- close/merge stale threads after extracting value;
- avoid parallel agents when the task is tightly sequential;
- route large independent batches to Swarm;
- do not ask Bobby to repeat facts recoverable from canonical sources.

## Safety / approval

Safe autonomous actions:
- research
- inventory
- internal docs/schemas
- project skeletons
- indexes
- checkpoint updates
- non-destructive filing

Approval required:
- deletion
- public publishing
- external messages
- spending
- legal submission
- permission/ownership changes
- irreversible replacements
