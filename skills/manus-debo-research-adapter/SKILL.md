# Manus DEBO Research & Skill Adapter v1.0

Owner: DEBO / Relay, Forge, Scout, Proof and Shield. Source candidate only; not installed in Manus merely by storing SKILL.md on GitHub.

## Choose what Manus actually adds
- For quick public facts, do the job in native ChatGPT or Perplexity Pro; do not start an expensive Manus task just to repeat an answer.
- Use Manus for genuinely multi-step browser, private-project file reconciliation, structured research plus artifact creation, or isolated code implementation when the target account has authorized tools.
- Use Manus Project instructions for repeated context, Skills for repeatable procedures, and Connectors only for actually authenticated provider accounts. Project instructions are not the same as all prior tasks being readable.
- The exposed ChatGPT Manus action here initiates a research task. It does not establish account-wide project/task/file enumeration, runtime model-selector access, or the ability to pull a report from every older task.

## Account inventory first
Apply \`cross-ai-artifact-inventory\` to enumerate actually visible Projects, Tasks, Skills, uploaded and generated files, version history, connectors, auth scopes, scheduled jobs, credits/usage when visible, and unfinished work. Treat saved task references as pointers, not completed reports. Preserve the existing R148 dashboard delegation, and do not launch a duplicate.
With no verified account-wide read route, create a copyable in-Manus instruction for an authenticated session rather than claiming access. Do not ask for passwords.

## Existing skill selection
Before building: inspect repository and Notion Skill Registry. Reuse \`skill-lifecycle-manager\`, \`multi-ai-router\`, relevant project adapter, and portable SKILL.md packages. Build a new Manus-native skill only if it has a distinct recurrent trigger and test cases. Manus supports project skill libraries and importing skills by .skill/.zip/GitHub link where the user's plan/workspace supports it; do not claim installation without a Manus readback.

## Research/implementation cycle
1. Scope mission, correct business owner, existing project and latest verified checkpoint, permissions, data classification and no-spend gate.
2. Identify target connectors and mode based on task, not on model marketing. Verify actual Manus task/workspace capabilities.
3. Use read-only source gathering first. Never send, buy, publish, deploy, delete, change permissions, contact customers or migrate production without explicit appropriate approval.
4. Produce inspectable artifacts with source URLs, SHA/version, manifest, tests actually run, unknown gaps, cost/credit observation (if available), and rollback.
5. Return a single structured packet to DEBO, mark write/readback truth, never self-approve.

## Manus output contract
MISSION_ID / PROJECT_ID / TASK_ID_AND_URL / ACCOUNT_SCOPE / CANONICAL_CHECKPOINT / CONNECTORS_ACTUALLY_USED / ARTIFACTS_FOUND_OR_CREATED / ORIGINAL_SOURCE_LINKS / SKILL_MATCHES_AND_GAPS / CODE_DIFF_OR_DOCS / TEST_RECEIPTS / PRIVACY_REVIEW / COST_OBSERVED_OR_UNKNOWN / STATUS / HELD_APPROVALS / NOTION_PRIVATE_WRITE_READBACK_OR_UNSAVED / EXACT_NEXT_STEP.

## Failure and negative checks
- Existing task already delegated: retrieve or continue it, don't relaunch.
- Unable to enumerate personal account: mark UNKNOWN, do not invent complete inventory.
- Connector listed but unauthenticated: do not run account actions.
- No verified readback: no "installed", "synced" or "live" claim.
- GitHub public repo: never include private Notion, claims, finance, youth, business client or account-identifying data.
