# DEBO Runtime Bootstrap
Before executing work in any DEBO master or sister-brain project:
1. Load the current generated brief for the resolved project under `governance/runtime-briefs/`, with `DEBO.md` for the master. Follow the [single canonical runtime bootstrap](governance/DEBO_RUNTIME_BOOTSTRAP_v2.md) for freshness, fallback and compact golden rules. With a checkout, `python tools/debo_bootstrap_check.py --brief --project DEBO` generates a view on demand. The [JARVIS policy](debo/policies/DEBO_JARVIS_AUTONOMOUS_V2.md) remains authoritative; load detailed policies for their relevant triggers.
2. For skill inventory or registry conflict work, use `tools/debo_skill_delta.py` (canonical) or `tools/debo_skill_delta_audit.py` (stable shortcut), guided by `docs/DEBO_SKILL_DELTA_README.md`. Compare `SKILL_REGISTRY.md` with the Notion **Skill Registry database** under the AI OS Hub; older summary counts are historical. These tools are read-only and not an automatic connector.
3. Load only the selected project profile and latest verified private checkpoint; a static profile is not live project state. Do not assume repository policy auto-injects into every chat.
4. Apply inherited defaults and project adapter; preserve approval boundaries.
5. Record evidence, decisions, version, tests, and next action.
6. For future projects, add a project adapter without duplicating master rules.
This bootstrap is persistent in GitHub, not proof of activation in external applications.
7. DEBO Dashboard is the official **read-only instrument panel**, not another brain, database, or approvals service. Its public Core source-health feed is generated by `tools/debo_dashboard_core_feed.py` from the same existing runtime-brief workflow at `governance/dashboard/DEBO_CORE_FEED_v1.json`. This feed contains public policy/source fingerprints and project routing identifiers **only**. It cannot establish live business status, read private records, approve changes, deploy apps, or replace permissioned project checkpoints. A dashboard client may check feed reachability on open but must label unknown/stale sources accurately and retain the v0.2.2 rollback.

8. **Continue-to-completion operating rule (2026-11-04):** When the next safe, authorized step is clear, execute it without asking for another “go,” stopping at a mere status update, or creating a checkpoint as a substitute for work. Recover existing sources, choose reversible low-risk methods, batch independent work, verify readbacks, and keep advancing until the objective is completed or a genuine external dependency, missing essential input, approval boundary, or tool limitation prevents further action. At a blocker, diagnose and try permitted alternatives, continue independent tasks, and ask only for the smallest necessary action. Never infer consent to spend, deploy, delete, change permissions, contact customers, access secrets, or bypass security. Report completed vs pending truthfully. This is a DEBO project rule, not proof that ChatGPT account-wide Memory or every other project has been updated.

9. **Elite execution-first default (2026-11-09):** For every substantial DEBO MASTER or sister-project request, follow the existing [Elite Execution Prompt v2](prompts/DEBO_ELITE_EXECUTION_PROMPT_v2.md) and its [machine-readable scope contract](governance/DEBO_ELITE_EXECUTION_DEFAULT_v1.json) as *additive routing guidance*, subordinate to this bootstrap, the JARVIS policy, current project adapter, and business-owner approvals. Mack is the single Chief of Staff; the existing 13 documented DEBO roles and task-specific specialists are functional assignments, not proof of separately running agents. Recover only the current relevant sources and latest verified checkpoint, then execute the highest-value safe reversible work, test changed behavior, and save one source-backed delta. Do not inflate progress through audits, prompt rewrites, artificial task counts, duplicated tools, fictional workers, or unverified speed claims. Use the existing R31 decision-router candidate only after its review and installation are verified; never silently replace a working runtime. Future prompts should be improved into compact outcome→authority→action→proof→checkpoint contracts automatically, without making a user repeatedly paste the prompt. This is **GitHub source policy only** until each supported ChatGPT project, agent runtime, external app, or other AI independently loads it and proves execution through a readback. No extra spending, plugin installation, public deployment, production write, cross-project private-data access, user permission change, customer contact, or automatic schedule is authorized by this rule.
