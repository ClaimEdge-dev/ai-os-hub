# DEBO AI output evaluations | R155 source-review adapter

**Status:** candidate on an isolated review branch; synthetic evaluator tested locally. No model calls, real agent runs, installation or production deployment. This is an additive extension to the existing R129 Promptfoo pilot, not a second skill factory or an independent AI judge.

## Evidence and rationale

- Official course: https://developer.chrome.com/docs/ai/evals
- Existing R129 Promptfoo provider tests deterministic R31 routing decisions and is deliberately not an LLM evaluation.
- The new quality_eval.py grades exported, sanitized AI-output claims against a 12-case synthetic rubric.
- The test suite checks both normal cases and negative mutations that must fail, with no API credentials.
- A passing score means the reported output matched the rubric. It is not proof that claimed tool actions occurred or that source links exist.

## Source files

- security/r129_promptfoo/quality_eval.py: standard-library evaluation runner; JSON report and per-criterion reasons.
- security/r129_promptfoo/fixtures/quality_cases.json: twelve handcrafted requirements covering reuse, truthful work status, owner gates, isolation, provenance, missing access, security and Launch Cal demo integrity.
- security/r129_promptfoo/fixtures/synthetic_outputs.json: handcrafted expected responses ONLY; these are not samples actually generated by DEBO.
- tests/test_debo_quality_eval.py: fifteen local regression tests, including incorrect status, missing evidence, unapproved actions, secrets, duplicate IDs and an empty dataset.

## Run from the repo root

    python -m unittest discover -s tests -p 'test_debo_quality_eval.py' -v

    python security/r129_promptfoo/quality_eval.py --cases security/r129_promptfoo/fixtures/quality_cases.json --outputs security/r129_promptfoo/fixtures/synthetic_outputs.json

The evaluator accepts a JSON list of structured captured outputs with case_id, status, answer, evidence_refs and claimed_actions. Missing cases fail; duplicate/unknown cases raise errors. Reports include total, passed, pass_rate, model_calls=0, PASS/FAIL and reasons. The script does not execute any action.

Keep actual model outputs and tool traces in their authorized private workspace until reviewed and redacted. Do not commit credentials, private business records or employee/customer data to this public repository. The model's own citations and claimed_actions are NOT trusted readbacks. Protected-action approval must come from the authorized owner and independently verifiable tool history.

## Quality ladder and release gates

1. **Rule-based unit tests (built, local-tested):** check output structure, status, allowed actions, source presence and secret-like material. These checks are intentionally narrow, can fail on negated wording, and do not prove factual accuracy.
2. **Real model/skill regression (not run):** capture actual DEBO and project-adapter responses. Verify evidence by connector readbacks and compare status to trusted action history.
3. **Subjective model-as-judge (not installed):** define binary rubrics for clarity, appropriateness, source relevance and useful next action; calibrate using separately human-labeled examples before measuring judge-model alignment. Do not incur API charges or broaden data access without approval.
4. **Held-out and adversarial evaluation (not run):** include incomplete inputs, no-activation cases, cross-tenant queries, prompt injection, unverified sources, conflicting versions, interrupted workflows and misleading tool output. Distinguish coverage and confidence from a single pass percentage.
5. **Proof/Shield/human acceptance (not run):** independent review and owner release decision. A judge score cannot authorize a merge, deploy, account change or private-data transfer.

**Launch Cal is not currently an AI application.** Its current UI and D1 tests measure ordinary software correctness. These AI eval cases apply only to future agent-generated release summaries and source-normalization workflows, especially the prohibition on treating fictional demo launch records as actual company commitments.
